# SDD — Backend Request Observability

Status: Implemented on `codex/observability-request-telemetry`
Basis: `upstream/main` `aad029a`, current code, Council review, and stale PR #162.

## Problem

The backend has a database readiness endpoint and business audit trail, but no
safe request correlation or operational request view for diagnosing failures.

## Scope

- Server-generated `X-Request-ID` on every response.
- Bounded request telemetry: method, sanitized path, status, duration, severity,
  and error type.
- Super Admin controls in `/admin/pengaturan`: enabled, capture requests,
  minimum level, sampling, and retention.
- Super Admin-only recent request log viewer.
- Non-secret configuration persisted additively in `AppConfig`.

## Non-goals

OpenTelemetry/exporters, time-series metrics, distributed tracing, alerting,
external log shipping, and request body/query/header capture.

## Invariants

- Authorization is enforced on the server for config and log reads.
- Request IDs are generated by the server and bounded.
- Dynamic path segments are redacted; no query string is recorded.
- Observability failures never change the primary response.
- Error events bypass sampling; normal events follow the configured sample rate.
- Logs are bounded in memory per process and expire by retention; they are not
  part of business AuditLog or participant/operator snapshots.

## Acceptance criteria

1. Every request response includes a valid `X-Request-ID`.
2. Super Admin can save and reload observability settings.
3. Unauthorized callers cannot read or mutate settings/logs.
4. Recent logs show only whitelisted, sanitized metadata.
5. Malformed persisted config fails closed without breaking requests.
6. Log buffer is bounded and retention is applied on write/read.
7. Existing health, audit, exam, and backup flows remain unchanged.
